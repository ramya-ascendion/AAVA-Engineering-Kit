# What the formatting gate installs in CI, pinned by hash.
#
# `.github/workflows/gates.yml` runs `black --check` on every pull request, and
# `pip install --require-hashes` is how that job gets black without running
# whatever PyPI served at job time on a runner holding the job's `GITHUB_TOKEN`.
# The same argument `tools/requirements-ci.txt` makes for PyYAML, and the same
# recipe: fetch a hash from `https://pypi.org/pypi/<name>/<version>/json` rather
# than dropping the pin.
#
# **Its own file rather than a second block in `requirements-ci.txt`**, because
# the document-structure job installs that one to answer three questions about
# file paths and has no use for a formatter.
#
# **Every package black imports is here, not just black.** `--require-hashes`
# refuses an install where anything is unpinned, so a closure with one package
# missing fails the job rather than resolving it quietly. The list came from
# `pip install --dry-run --report -` resolved for the runner — Linux x86-64,
# CPython 3.12 — which is seven packages. `colorama`, `tomli` and
# `typing-extensions` are in black's metadata behind environment markers that are
# false on that platform, so adding them would pin things the job never installs.
#
# **This file is the one place the CI black version is named.** A project that
# also pins black in its own dev dependencies must keep the two equal, or CI and
# a developer's checkout format differently.
#
# Two hashes per package: the wheel the runner takes and the source distribution
# as the fallback. black and pytokens ship a compiled wheel as well, so they get
# three.
